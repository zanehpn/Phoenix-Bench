The bug is localized in `src/axi_xbar.sv` at the instance of `axi_err_slv`.

### Root cause
`axi_err_slv` declares:

- `input req_t slv_req_i`
- `output resp_t slv_resp_o`

But in `axi_xbar.sv`, the error slave is instantiated with a **part-select of an unpacked array element**:

```systemverilog
.slv_resp_o ( slv_resps[i][Cfg.NoMstPorts] )
```

Older ModelSim/Questa versions (like 10.6c) can reject this as an illegal output/inout connection, even though the RTL is otherwise valid. The safe workaround is to connect the error slave to a temporary signal, then assign that signal into the array element.
