The issue localizes to two places:

1. `src/axi_pkg.sv`
   - `resp_t` is already a package typedef:
     ```systemverilog
     typedef logic [1:0] resp_t;
     ```
   - But the typedef macros in `include/axi/typedef.svh` also use `resp_t` as a struct name parameter in several places, which can confuse Verilator when expanded in the same scope.

2. `include/axi/typedef.svh`
   - The problematic macro parameter name is `resp_t` in `AXI_TYPEDEF_RESP_T` and `AXI_LITE_TYPEDEF_RESP_T`.
   - Renaming the macro parameter to something like `rsp_t` avoids the clash without changing the generated type names for users who instantiate the macro.
