The bug is in `src/axi_lite_regs.sv`, in the read datapath.

### Localization
The failure is caused by the module allowing a **read to complete in the same cycle that a conflicting direct load (`reg_load_i`) happens on bytes from the same chunk**. Since `reg_d` is updated combinationally from `reg_load_i` before the read data is formed, a randomized `rand_load` can sometimes overwrite bytes just before the read response is captured, producing a mixed value like `de01beef` instead of the expected constant `DEADBEEFDEADBEEF`.

The module already stalls **writes** on chunk-load conflicts, but it does **not** stall **reads**. For this design, reads must also be held off whenever a direct load is active on bytes that are being read in the current chunk.

## Fix
Add read-side conflict detection and prevent read completion when any byte in the addressed chunk is directly loaded in the same cycle.
