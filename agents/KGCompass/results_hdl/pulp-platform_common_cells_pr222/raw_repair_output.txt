The bug is in `src/stream_arbiter_flushable.sv`.

### Localization
For `ARBITER == "prio"`, the module instantiates `rr_arb_tree` with:
- `ExtPrio = 1'b1`
- `LockIn  = 1'b1`

But `rr_arb_tree.sv` explicitly asserts that `LockIn` may only be used when `ExtPrio` is `1'b0` (see the assertion around the `LockIn` logic). So priority arbitration is incorrectly wired through the round-robin arbiter with an invalid parameter combination.

### Fix
For priority arbitration, keep external priority enabled but **disable `LockIn`**. That avoids the assertion and matches the intended behavior of static priority arbitration.
