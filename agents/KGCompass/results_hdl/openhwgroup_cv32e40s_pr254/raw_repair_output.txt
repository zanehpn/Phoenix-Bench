The bug is in the RVFI PMP address plumbing between:

- `rtl/cv32e40s_cs_registers.sv` — PMP address storage is only `PMP_ADDR_WIDTH` wide
- `bhv/cv32e40s_rvfi.sv` — RVFI expects `csr_pmpaddr_q_i` to be 32 bits wide
- `bhv/cv32e40s_wrapper.sv` — the wrapper connects the narrower RTL signal directly to the RVFI port

The clean fix is to zero-extend the internal PMP address value to 32 bits before exposing it to RVFI, so the RVFI interface sees the expected width and the CSR value is correct in formal.

=======
    input logic [31:0]                         csr_pmpaddr_n_i, // PMP address input shared for all pmpaddr registers
    input logic [31:0]                         csr_pmpaddr_q_i[PMP_MAX_REGIONS],
>>>>>>> REPLACE
