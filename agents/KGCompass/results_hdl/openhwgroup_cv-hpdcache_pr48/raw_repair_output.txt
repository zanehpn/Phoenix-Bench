The bug is in `rtl/src/hpdcache_ctrl_pe.sv`.

### Localization
`evt_write_req_o` is currently emitted only when a write miss is first detected on the core request path, but not when the request is replayed from the RTAB after a memory response with the error bit set. In that case, the replayed store can effectively complete without ever flagging the write request event.

A robust fix is to emit `evt_write_req_o` for write-back stores both:
- on the original cache hit path, and
- when the request is replayed from the RTAB after a miss.

This matches the second proposed solution in the issue description and avoids missing the event on error-replay cases.
