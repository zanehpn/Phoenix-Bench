The bug is in `src/clk_int_div.sv`, inside the `WAIT_END_PERIOD` state.  
When `div_q == 0`, the condition

```systemverilog
if (cycle_cntr_q == div_q - 1)
```

becomes effectively impossible to satisfy because `div_q - 1` underflows for an unsigned value. That leaves the FSM stuck in `WAIT_END_PERIOD`, preventing further reconfiguration.

A safe fix is to treat divider values `0` and `1` as bypass mode in the transition logic as well, so the FSM can always exit `WAIT_END_PERIOD`.
