The bug is in `src/dm_sba.sv`.

### Localization
In the `Read` state, `be` is set to `be_mask`, but `be_mask` is only driven in a separate `always_comb` block and `be_idx` is also assigned in `p_fsm`. As written, the byte-enable generation can end up not behaving like the `Write` path, especially for reads where `_be` should reflect the selected access size and address alignment just like writes.

The issue text suggests the read path should use the same `_be` handling as write. The clean fix is to initialize and compute `be_mask` deterministically in the same combinational flow, so reads and writes both use the same byte-enable value.
