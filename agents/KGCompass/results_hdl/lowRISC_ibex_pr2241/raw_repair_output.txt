The bug is in `rtl/ibex_register_file_fpga.sv`.

### What’s wrong
`oh_raddr_a_err` and `oh_raddr_b_err` are declared unconditionally, but they are only driven inside the `if (RdataMuxCheck)` generate block. When `RdataMuxCheck == 0`, they remain undriven, which triggers Verilator’s `UNDRIVEN` warning.

The FF-based register file (`rtl/ibex_register_file_ff.sv`) already handles this correctly by assigning `1'b0` to those signals in the `else` branch.

### Fix
Add an `else` branch to `ibex_register_file_fpga.sv` that drives:
- `oh_raddr_a_err = 1'b0`
- `oh_raddr_b_err = 1'b0`

This keeps behavior consistent and lint-clean.
