The inconsistency is localized in `rtl/src/hpdcache_victim_plru.sv`.

### Root cause
`hpdcache_victim_plru` only updates PLRU state when `updt_i` is asserted, and the update value comes directly from `updt_way_i`.  
For normal accesses, `updt_way_i` is the accessed way on hit, or the allocated/refilled way on miss.

For `CMO_PREFETCH` with `prefetch_updt_plru == 1`, the miss path updates PLRU on refill completion, but the hit path does not appear to generate a corresponding PLRU update pulse. That makes the behavior inconsistent.

The fix is to ensure the PLRU update logic is triggered consistently for prefetch hits as well, by using the same update mechanism already used for misses.
