The likely issue is in `src/shift_reg.sv`: it currently only supports a plain shift register with no `valid` control, so it cannot be power-gated/clock-gated selectively for the internal datapath. The new requested version should be backward compatible while adding an optional `valid_i`/`valid_o` path so tools can infer ICG on the internal flops when data is valid.

A minimal, backward-compatible fix is to extend `shift_reg` with an optional valid flag and use it to gate the register update. Since the existing file has no valid-related ports, the fix should preserve old behavior when valid is not used.
