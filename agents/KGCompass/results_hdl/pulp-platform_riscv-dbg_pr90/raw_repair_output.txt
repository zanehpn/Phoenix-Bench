The bug is in `src/dm_mem.sv`, in the abstract-command ROM generation for the “two scratch CSRs implemented” case.

### What’s wrong
The issue report is correct that the comment near the `dscratch1` access is misleading. More importantly, the generated debug ROM for the two-scratch case is using the wrong instruction sequence for the `a0` save/restore path: it should not redundantly move the same value between `a0` and `dscratch1` when `a0` is already being preserved by the program flow.

The localized fix is in the ROM content generation in `dm_mem.sv` and the corresponding generated ROM image file(s), where the instruction sequence for the two-scratch variant should be corrected.
