The bug is in the **instruction fetch/PMP interaction**, specifically in the fetch path when an instruction **straddles a PMP region boundary**.

### Localization
- The PMP logic itself (`rtl/ibex_pmp.sv`) appears to compute TOR matching correctly for a single address.
- The issue is that **Ibex only appears to check the fetch address once per instruction fetch**, while a straddling instruction needs **a second PMP check for the upper halfword / second fetch beat**.
- In this repository, the relevant place is the **IF stage**, where instruction fetch errors are assembled from:
  - `pmp_err_if_i`
  - `pmp_err_if_plus2_i`
  - fetch buffering / alignment logic

The likely bug is that the **plus-2 fetch path is not being treated as an instruction access fault for the straddling case**.

A good fix is to ensure the IF stage propagates and prioritizes the `plus2` PMP fault for compressed/instruction boundary straddling in the same way it already does for bus errors.
