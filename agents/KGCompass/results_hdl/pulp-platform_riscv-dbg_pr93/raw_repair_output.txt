The bug is in `src/dm_sba.sv`.

### Localization
`sbdata_valid_o` is currently tied directly to `master_r_valid_i`:

```systemverilog
assign sbdata_valid_o  = master_r_valid_i;
```

This means the SBA state machine advances as soon as the bus response is available, but `dmi_resp_valid_o` in the higher-level DM path can still be produced independently of the actual master read completion. In fast/slow simulation mismatches, this can cause burst read data to be observed too early, resulting in dropped/interleaved reads as described.

The fix is to defer completion of the SBA read transaction until the master read data is actually valid, so the response presented to the DMI side only advances when `master_r_valid_i` is asserted.
