The bug is in the performance-counter retire path, specifically `rtl/cve2_wb.sv`.

### Localization
`perf_instr_ret_wb_o` currently increments for any instruction that reaches writeback, except LSU response errors. That misses the case where `DRET` executed in Machine mode is illegal and causes an exception/trap, so it should not be counted as retired.

The clean fix is to gate instruction retirement on the same “valid retired instruction” condition used by the core’s performance counting path, not just the WB enable and LSU error check.
