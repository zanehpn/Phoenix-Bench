The bug is in `src/dm_csrs.sv`, in the `Data0..DataEnd` read/write handling.

### Why this is the bug
Per spec, any access to `data0` while an abstract command is executing must set `cmderr = busy` if it is currently `0`.

In the current code, the `Data0` access path only checks `cmdbusy_i` to decide whether to auto-execute, but it does **not** raise `cmderr` when a debugger accesses `data0` while busy. So the illegal concurrent access is silently accepted.

---

## Fix
When `data0..dataN` is accessed and `cmdbusy_i` is asserted, set `cmderr_d` to `CmdErrBusy` if it is still `CmdErrNone`.
