The issue is localized in `src/stream_join.sv`.

### What’s wrong
Current `stream_join` is a pure combinational AND-reduction join:
- it always waits for **all** input `valid`s
- it grants **all** `ready`s simultaneously

That matches the old “specular to fork” behavior, but it does **not** support:
1. selecting only a subset of inputs to join dynamically
2. independent input handshakes

To fix the feature request, the join must be extended into a dynamic-select join with per-input independent ready generation, analogous to `stream_fork_dynamic`.

/// stream.  The selection is provided through a bitmask, and selected inputs handshakes are
/// granted independently.  The output handshake happens only once all selected inputs are valid.
/// The data channel flows outside of this module.
module stream_join_dynamic #(
  /// Number of input streams
  parameter int unsigned N_INP = 32'd0 // Synopsys DC requires a default value for parameters.

  /// Input streams valid handshakes
  input  logic  [N_INP-1:0] inp_valid_i,
  /// Input streams ready handshakes
  output logic  [N_INP-1:0] inp_ready_o,
