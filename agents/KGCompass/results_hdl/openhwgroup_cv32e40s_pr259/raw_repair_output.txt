The bug is localized in **`rtl/cv32e40s_pmp.sv`**, in the **access-fault prioritization** logic.

### Root cause
When `mseccfg.MML` is set and **no PMP region matches**, the current code still leaves `access_fault` at:

- `mmwp || (priv_lvl_i != PRIV_LVL_M)`

So for **M-mode with `MMWP=0`**, `access_fault` becomes `0` by default, which incorrectly allows execution through unmapped memory.  
Per Smepmp, with **MML set**, access should be denied unless a matching rule explicitly allows it.

### Fix
Make the default deny behavior apply whenever **MML is set**, even if no region matches.
