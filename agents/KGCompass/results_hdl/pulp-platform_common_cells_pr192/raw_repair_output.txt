The bug is in `src/onehot_to_bin.sv`, specifically this line inside the nested generate loop:

- `assign tmp_i = i;`

Here `i` is a `genvar` and is treated as a 32-bit value by some strict compilers (like VCS), while `tmp_i` is parameterized to `BIN_WIDTH`. This can trigger a width mismatch.

A generic fix is to explicitly slice/cast `i` down to `BIN_WIDTH` bits before assignment.

```systemverilog
### src/onehot_to_bin.sv
<<<<<<< SEARCH
                assign tmp_i = i;
=======
                assign tmp_i = i[BIN_WIDTH-1:0];
>>>>>>> REPLACE
```
